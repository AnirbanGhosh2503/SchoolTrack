## 1. Project Overview

SchoolTrack is a proposed RFID-based Student Movement Management System intended to provide an educational institution with an independent and centralised mechanism for collecting, storing, processing and accessing student movement information.

The proposed system will integrate RFID-based identification hardware with a software platform capable of managing student records, tracking movement events, monitoring attendance and recording transportation-related activities.

A web-based administrative interface is proposed to facilitate convenient access to the system by authorised institutional personnel.

The project aims to reduce dependency on external data management services and provide the institution with greater control over its operational information.

## 2. Project Background and Justification

The institution currently employs an RFID-based identification system for monitoring student movements, including entry into and exit from school premises and boarding and deboarding of school buses.

However, limitations in independently accessing and managing the information generated by the existing system have created a need for an institution-controlled alternative.

The proposed project seeks to address this requirement through the development of an integrated hardware and software solution.

The system is intended to improve information accessibility, administrative efficiency, data ownership and flexibility in managing student movement records.

## 3. Project Vision

To develop a reliable, secure and institution-controlled RFID-based student movement management platform that enables authorised personnel to access and manage student movement information efficiently, independently and transparently.

## 4. Project Objectives

The primary objectives are:

1. To design and develop an RFID-based student identification and movement tracking system.
2. To establish a centralised database for student information, RFID card assignments and movement records.
3. To implement automated recording of student entry and exit events at designated school checkpoints.
4. To facilitate monitoring of student boarding and deboarding activities on school buses.
5. To develop a web-based dashboard for authorised institutional personnel.
6. To provide search, filtering and reporting facilities for student movement information.
7. To support the export of relevant records in CSV, Excel and PDF formats.
8. To establish appropriate authentication, authorisation and data security mechanisms.
9. To minimise dependency on external data management providers.
10. To develop a system architecture that can accommodate future institutional requirements.

## 5. Preliminary Project Scope

The initial scope of the project includes:

These features may be considered for future development after evaluating institutional requirements.

## 8. Preliminary Technical Direction

The project is expected to adopt a modular hardware-software architecture consisting of:

- RFID identification hardware.
- Embedded controllers and associated firmware.
- Device communication interfaces.
- Backend application and REST APIs.
- Centralised database.
- Web-based frontend.
- Reporting and data export modules.

A cloud-hosted database and application deployment are being considered as the initial architectural direction.

MongoDB Atlas is a candidate database platform. Final technology selection will follow technical evaluation and feasibility analysis.

The system should also consider temporary local event storage and synchronisation mechanisms for devices operating without continuous internet connectivity.

## 10. Preliminary Constraints and Assumptions

### 10.1 Constraints

- The system is expected to support approximately 2,000 students.
- Hardware specifications are yet to be determined.
- Existing RFID hardware compatibility is unknown.
- Internet connectivity at different locations, particularly on buses, may vary.
- The project budget and deployment infrastructure are yet to be confirmed.
- Access to the existing system's technical documentation may be limited.

### 10.2 Assumptions

- Each student will be assigned a uniquely identifiable RFID card.
- RFID readers will be installed at designated checkpoints.
- The institution will provide the necessary student information for authorised system operation.
- Authorised institutional personnel will be available for requirements gathering and system evaluation.
- The institution will consider an independently managed software platform.
- Cloud deployment is a proposed option, subject to institutional approval.

## 12. Project Success Criteria

The project will be considered successful when:

1. The system can maintain and retrieve records for the intended student population.
2. RFID devices can successfully identify registered cards.
3. Valid movement events are recorded and associated with the correct student and device.
4. School entry and exit records can be retrieved and reported.
5. Bus boarding and deboarding records can be managed.
6. Authorised users can access the appropriate dashboard functionalities.
7. Reports can be generated and exported in the supported formats.
8. Security and access control mechanisms function as intended.
9. The system passes the defined integration and acceptance tests.
10. The institution can independently administer its system and access its data.

Quantitative performance targets will be established during requirements engineering and testing.
